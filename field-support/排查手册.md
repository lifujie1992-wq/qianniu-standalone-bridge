# 千牛助手 - 现场诊断采集（只读，不改任何设置）

用途：在出问题的客服机上双击运行，把当前状态抓成一个压缩包发回技术同学。
特点：
- 不安装任何东西，只用 Windows 自带的 PowerShell
- 不重启千牛、不模拟键鼠、不截屏、不发消息
- 自动把 token 等敏感字段打码后再写入报告

## 怎么跑

双击 `诊断-双击我.cmd`，等它跑完（约 30~60 秒）。
桌面会生成：

```
千牛诊断-<机器名>-<时间>.zip
```

把这个 zip 发回技术同学即可。

## 它采集了什么

| 项 | 说明 |
|---|---|
| 助手版本 / 构建号 | `/api/v1/status` |
| 页面连接数、挂钩情况 | `bridge.browser.hook_summary` |
| 每个千牛页面 | URL、标题、是否挂了 imsdk（CDP 可用时） |
| 页面能力探测 | `imsdk` / `imsdk2` / `QN.app` / `workbench` 各自的 typeof（1.6.42+ 才有） |
| 商品 / 订单实调 | 真打一次 mtop，记录成功或**每条通道的具体失败原因** |
| 未送达队列 / 上下文补全 | `context_enrich` 计数与最近错误 |
| 客户端指纹 | 千牛版本、`AppBiz.dll` 大小+sha256、`webui.zip` 大小+sha256 |
| webui 页面类型 | zip 里是 `web_chat-packer/recent.html` 还是 `dx-h5/index.html` |
| 运行目录 | `runtime/` 下有哪些客户端版本、各自是否已注入 |
| 日志尾部 | `state\standalone_bridge.log` 最后 300 行 |

## 报告怎么看（给技术同学）

先看 `summary.txt`，重点三行：

```
挂钩        : 6/6  chat_page_present=True
商品查询    : OK 3/1240          或  FAIL <原因>
订单查询    : OK 买家xxxxxxxxx 2 单 或  FAIL <原因>
```

判读：

| 现象 | 含义 | 处理 |
|---|---|---|
| 商品 OK、订单 FAIL | 买家 ID 取不到或该买家确实没单 | 看 `orders.error`、换一个最近会话再试 |
| 商品 FAIL `no mtop channel` | 页面里没有任何取单桥 | 看 `channels.QN_typeof`，再决定切页面/升级 |
| 商品 FAIL `workbench is not defined` | 壳子缺原生 workbench（dx-h5 形态） | 参考 `千牛9.98.49N-dx-h5无法取订单-反馈.md` |
| 商品 OK 但订单空 | mtop 通了，该买家 0 单 | 正常，不是故障 |
| 挂钩 0/N | 注入没成功 | 看 `client_support` 与 `webui_injected` |
| `status` 很慢/超时 | 1.6.49 及更早的已知缺陷 | 升级到 1.6.50+ |

## 想手工调接口

```powershell
$cfg   = Get-Content C:\ai\QianniuAIService\config.json -Raw | ConvertFrom-Json
$h     = @{ "X-Workbench-Token" = $cfg.workbench_token }
$base  = "http://127.0.0.1:$($cfg.workbench_port)"

Invoke-RestMethod "$base/api/v1/status" -Headers $h | ConvertTo-Json -Depth 6
Invoke-RestMethod "$base/api/v1/catalog/channels" -Headers $h | ConvertTo-Json -Depth 4
Invoke-RestMethod "$base/api/v1/catalog/goods?page_no=1&page_size=3" -Headers $h
Invoke-RestMethod "$base/api/v1/catalog/orders?buyer_encrypt_id=782486237" -Headers $h

# 1.6.47+ 可指定通道，用来逐条验证哪个桥能取数
Invoke-RestMethod "$base/api/v1/catalog/orders?buyer_encrypt_id=782486237&channel=qn_app" -Headers $h
# 可选通道：imsdk / imsdk2 / qn_app / qn_application / QNAbilityCenter / abilitycenter
```

## 源码怎么用

包内是完整源码（与 GitHub main 一致）。有 Python 3 的机器可以：

```powershell
python tools/check_client_support.py --root C:\ai\QianniuAIService
python tools/qn_catalog_cli.py --help
python -m unittest discover -s tests
```

没有 Python 也没关系：诊断脚本已经把需要的现场信息全采了。
