# 1.6.19 自测修复与会话跳转优化

## 合并来源

- `feat/transfer-history-image-probe-20261020`（含 1.6.18 的诊断开关）。
- `fix/native-image-url-lookup-20261020` 的 `628c37c`（原生图片 URL 回查）。

## 实际复现并修复

1. 买家和我方消息的平台时间精度只有秒时，旧消息可能覆盖列表摘要，
   买家在我方回复后发来的同秒消息也可能没有倒计时。用首次入库顺序处理
   同秒消息，不修改 buyer_id、msg_id 或原始时间字段。
2. 原生人工回复通知使用 `strFullEvent` 时未记入回复回执；补齐兼容。
3. 历史诊断参数可以覆盖真实 ccode；现在以转接事件的会话 ID 为准。
   SDK 暂未就绪时不再提前耗尽该会话的一次诊断机会。
4. 原生图片查找可能用同会话的一张旧图替代未匹配的新消息。现在有消息 ID
   就必须精确匹配。图片说明文字保留，普通文字中的 `[图片]` 不被替换。
5. 多网页连接时，空缓存页面可能先回答，掩盖另一个网页的真实图片 URL。
   现在共享一次超时并等待有效结果，及时清理待响应请求。
6. 重复点击已打开的会话时，千牛可能不再发切换通知，旧版会等待 3 秒并
   提示未确认。现在维护独立的当前会话观察游标，严格匹配运行中千牛 PID、
   店铺和完整 ccode；每次仍调用跳转命令。手动切换和进程重启会使旧观察失效，
   大量日志积压时不会复用不确定的旧状态。
7. 先切换目标会话再激活窗口，减少旧会话的多余渲染。浮窗立即提示正在打开。
8. 详情页原手动发送入口会被服务端的“大脑指令授权”规则拒绝；改为
   “在千牛回复”，保留服务端发送限制。

## 验证

- 隔离测试禁止访问正式大脑和本机正式服务端口；使用临时数据库、模拟发送
  回执及模拟网页。另有真实千牛会话切换验证，不向买家发送测试消息。
- 373 项原有及新增测试的最终结果：372 项通过、0 失败、0 错误、1 项跳过。
  跳过项要求源码目录内带完整 runtime/vendor；
  安装包另做文件与运行状态检查。
- JavaScript 行为测试 35 项通过，包含历史探测和图片精确匹配。
- 优化源码在本机真实千牛测得两次切换 529 / 1502 ms，随后重复点击为 21 ms；
  均核对了目标 ccode。千牛新会话的实际加载耗时仍随会话内容变化。
- 本机 13 个已有会话均有有效昵称。尚未在其他电脑复测；图片 URL 能否取得
  仍取决于千牛是否在连接网页中提供本地消息缓存。
