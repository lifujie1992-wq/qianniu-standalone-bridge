# 原生接待通道昵称补全

## 原因

原生 AppBiz 消息回调可以正常接收消息，但 buyer_nick 可能只有数字 ID。
仅有 dx-h5 卡片页面连接时，页面没有 imsdk、workbench 或会话缓存，原有
GetUserNick / 会话列表回查无法运行。浏览器连接数不能证明昵称接口可用。

## 修复

- 增加独立后台昵称解析器，只读千牛自身 app.log 中的结构化 IM 和会话通知。
  对应事件包括 onShopRobotReceriveNewMsgs、onReceiveNewMsg 和
  onConversationChange；同时支持会话元数据和带明确买家身份的发送者昵称。
- 必须同时匹配日志头的登录账号、完整 ccode 及其买家 targetId，拒绝数字
  占位符、账号冲突和店铺客服昵称。转交消息的客服发送者不能充当买家昵称。
- 新消息优先带上已知的真实昵称；缺失时异步补全，成功后走现有
  nickname_update 通道。使用已有 account + buyer_id 持久缓存，不重放聊天
  正文、不触发历史回复，不修改原消息 ID、买家 ID 或时间戳。
- 启动及每分钟扫描最近 24 小时的缺名会话。日志按增量读取，支持截断和
  轮转，限制初始读取范围、单轮字节量、行长度和内存映射大小。
- 保留原有 SDK 联系人回查。可通过内部配置 qianniu_log_dir 指定非标准
  千牛日志目录；日志不存在或格式不支持时，诊断状态会显示不可用。
- 当前对话标题随昵称回填刷新，保留输入框内容和当前会话。

## 本机观察

修复应用后，两条原先只显示买家 ID 的已有会话自动获得真实昵称；工作台
会话接口及浏览器列表均显示更新结果。桥接新增 nicknames 诊断状态，包括
pending、resolved、native_log_available 和 last_error。

没有发送验收消息或重发历史消息；未运行自动化测试。已完成源码语法检查。
昵称能力仍以千牛实际提供的消息/会话元数据为准；没有权威映射时保持为空。
